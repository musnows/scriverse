AI SAFETY · TOOL CALL LIMIT

全局工具调用限制

当 Agent 反复调用工具、上下文被 Compact 压缩后仍继续同一行为时，系统需要一道不会被 Compact 重置的熔断阀。 「全局倍数」就是这道阀：用「调用上限 × 倍数」限制单次回答里的工具总次数，避免无限消耗 Token。

书籍 AI 设置 默认调用次数 20 默认倍数 3 可选 1–6 不因 Compact 回退

它解决什么问题

叙界在一次 AI 回答中会给 Agent 配置「调用上限」（例如 20 或 30）。工具结果塞满上下文后会触发 Compact：压缩已完成的工具上下文，并把当前轮剩余次数放宽为约 上限 × 0.8（实现上是把已用次数重置为 上限 × 0.2）。

调用上限本身不会因为 Compact 变小。若模型在 Compact 后仍重复检索同一类工具，就会出现：

  1. 01调用工具 → 上下文接近上限 → 触发 Compact → 当前轮配额被放宽
  2. 02继续调用工具 → 上下文再次逼近上限 → 再次 Compact
  3. 03循环往复，会话难以自然结束，Token 持续消耗

两项设置分别做什么

调用上限

控制「当前轮」最多能执行多少次工具。最小值为 10，默认值为 20，服务端默认最大值为 300。 可以通过环境变量 SCRIVERSE_MAX_AGENT_TOOL_CALL_LIMIT 调整最大值，服务端会将最终最大值限制在 10–1000 之间。 页面会读取服务端返回的最大值；提交超过当前最大值时，会提示“Agent 工具调用上限不能超过 X 次”。快用尽时会在工具结果里注入提醒，催促模型收敛作答。

全局倍数

控制「整次回答」的硬上限：全局上限 = 调用上限 × 全局倍数。 计数器在本次回答周期内只增不减，Compact 与轮次重置都不会清零。 工具请求超过剩余额度时，对话会明确显示上限、已用次数和本次请求次数，保留已有回复与执行过程，并正常结束本次响应。

为什么默认是 3 倍

以调用上限 N = 15、全局倍数 3 为例，全局上限为 45：

阶段 发生了什么 全局计数
第 1 轮 用满约 15 次后 Compact，再继续约 12 次 约 27
第 2 轮 新一轮又接近上限并再次 Compact，继续调用数次 很快逼近 45
熔断 第二次 Compact 后不久触发全局上限，强制结束 ≥ 45
设计意图：允许一次「压缩后重试」；若 Compact 后仍重复同一路径，大概率是死循环，应尽快止损。 倍数越大，容错越高、止损越慢；设为 1 时全局上限等于调用上限，最严格。

如何选择

  • 1：最省 Token。适合工具结果已经很够用、只想防止任何跨 Compact 加码的场景。
  • 2–3（推荐）：给一次 Compact 重试空间，仍能较快熔断异常循环。
  • 4–6：长文检索、多卷交叉核对等确实需要更多工具轮次时再提高。

两项设置都在本书 AI 设置中独立保存，只影响当前作品，不会改动其他书的配额。

和 Prompt Cache 的关系

调用上限与全局倍数不会改动 Agent 请求的 prompt cache 前缀：不增删工具定义、不调整工具顺序、不改 tool_choice，也不因剩余次数改写系统提示。配额提醒只写在当次工具结果（请求后缀）里；真正会重建 cache 的是工具上下文 Compact（压缩摘要插入消息序列后，后续前缀必然变化）。

同理，作品设置里增减「AI 查询工具」只影响新对话。每个对话在创建时锁定工具集，已开始的对话中途改设置不会改变该对话后续请求的 tools 前缀。

和「调用上限」提醒的关系

当前轮剩余次数进入软提醒区间时，工具结果会附带 [warning] / [critical] 提示，引导模型尽快总结。 全局倍数是另一层硬限制：即使 Compact 反复放宽当前轮配额，总次数仍不能超过全局上限。

本文对应叙界书籍 AI 设置中的「Agent 工具调用上限 / 全局倍数」。
